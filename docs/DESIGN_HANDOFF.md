# Передача сайта следующему агенту

Актуально: 17 октября 2026. Репозиторий: Bogersebekov/website-own-v1. Ветка дизайна: `feat/home-poster-v1`.

## Что здесь находится

Рабочие исходники сайта на **Astro 7**, TypeScript, CSS и Markdown. Astro — фреймворк; компоненты используют HTML-разметку, JavaScript/TypeScript и CSS. `npm run build` собирает статический HTML в `dist/`. Скачиваемый ZIP — копия для просмотра; редактировать и развивать нужно этот репозиторий, а не собранные HTML-файлы.

Утверждён стиль **«Срезанные углы»**: тёмный фон, оранжевая дымка, тонкие тёплые кромки, контурные CTA без стрелок. На главной оранжевым выделены «консалтинговую фирму». Последние прямые решения владельца в этой инструкции и docs/site-content-2026-10-16/ имеют приоритет над старыми описаниями дизайна в README и CLAUDE.md: синие кнопки и линейная документная верстка больше не являются выбранным вариантом. Запись прогресса идёт в репозитории; отдельная синхронизация с Notion не нужна.

## Запуск

Node.js 24, npm. Из корня репозитория:

```sh
npm ci
npm run dev -- --host 0.0.0.0
npm run build
```

Команда `npm run check` объявлена, но требует ещё не установленных @astrojs/check и TypeScript; её успешное выполнение не заявлялось. Проверка текущей версии: production-сборка и Chromium, пять основных страниц на 320/390/768/1440 px, навигация, галереи, FAQ.

Общий каркас, меню, футер, просмотр скриншотов: `src/layouts/Studio.astro`. Обёртка внутренних страниц: `src/components/StudioDetail.astro`.

Главная и общие тексты/ссылки: `src/data/site.ru.ts`. Telegram: `site.links.telegram`. Исходники утверждённых внутренних текстов: `src/content/site-pages/`. Компонент агентства читает свой Markdown напрямую; остальные три имеют соответствующие тексты внутри компонентов.

Стили загружаются слоями: `studio.css` → `portrait-lab.css` → `site-editions.css` → `typography-refinements.css`. Последний слой содержит актуальные переопределения. У внутренних компонентов свой scoped CSS. Исторические /variants/, /looks/, /preview/, /refine/ сохранены; основные страницы используют `edition="type" refinement="facet"`. Не переключать основные страницы на старый Markdown-рендер.

Фотография, прозрачный портрет, дымовые фоны и три реальных скриншота кейса: `src/assets/materials/`. Шрифты и лицензии: `src/assets/fonts/`.

## Что подтверждено

- На главной семь блоков: первый экран, фирма, проекты, услуги, кейс, интервью, приглашение. Отдельного личного блога нет.
- Кейс: **$35 000+**, знак доллара слева; «Выручка, сгенерированная за 3 месяца». Четыре лендинга, **8 воронок** (без «более»), 13 кастдевов. Июнь–октябрь 2025; «Полное продюсирование» отдельной строкой.
- Внутренние страницы специально переработаны в карточки и отдельные композиции: услуги и их состав, раскрывающиеся FAQ, карточки гостей/результатов, схема и модули Life.OS, ресурсы и проекты фирмы.
- Не выдумывать URL соцсетей, ссылку на шаблон Life.OS, новые кейсы, цифры или готовых участников. Для отсутствующих адресов использовать подтверждённые данные владельца. Заглушки YouTube/Instagram в футере пока текстовые.

## Следующие задачи

Подключить предоставленные владельцем ссылки и проверить назначения CTA; уточнить точный шрифт логотипа; добавлять реальные материалы по мере получения; дорабатывать страницы по обратной связи. Сохранять исходники в этой ветке или создать новую от неё. В `main` не сливать без отдельного указания: push/merge в main запускает деплой через GitHub Actions.

Экспорт просмотра: после сборки `python scripts/export-preview.py /tmp/jetix-preview/offline selected`. Указанная папка должна быть вне исходников. ZIP не заменяет исходники в GitHub.
